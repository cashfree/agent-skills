# Migrating From Juspay to Cashfree Payments

> **References available:** This SKILL.md covers the migration path and the highest-risk rewrites. For the exhaustive endpoint map, field-level diffs, Hypercheckout / Express Checkout handoff changes, per-language SDK rewrites, webhook/event translation, refund/subscription/mobile mapping, and orchestrator exit checklist — read `references/REFERENCE.md` in this directory.

---

## 1. Scope & Boundaries

### When to use this skill

- The codebase already integrates **Juspay** through `https://api.juspay.in` or `https://sandbox.juspay.in`, sends `x-merchantid` / `x-routing-id`, uses Basic Auth with an API key, or handles `sdk_payload`, `client_auth_token`, `payment_links`, `ORDER_SUCCEEDED`, `ORDER_FAILED`, or `ORDER_REFUNDED`.
- The frontend uses **Hypercheckout / Express Checkout** concepts such as `process(...)`, Hyper SDK callbacks, or payment links generated by Juspay.
- The developer wants to **replace Juspay as the payment layer** with a direct Cashfree integration while preserving the merchant's checkout and fulfilment flow.
- You need to rewrite Orders, Checkout, Status Verification, Webhooks, Refunds, or Mandate / Subscription code from Juspay to Cashfree.

### When NOT to use this skill

- The project has **no existing Juspay code**. Use `getting-started/SKILL.md` and the relevant `pg/*/SKILL.md` files instead.
- The merchant still needs **Juspay's orchestration layer**: multi-gateway routing, fallback, unified payment method discovery, or Juspay analytics dashboards. Cashfree is a direct PG integration, not a drop-in payment orchestrator replacement.
- The ask is only about a specific Cashfree product such as `subscriptions`, `token-vault`, `payment-links`, or `payouts` without a broader Juspay migration. Go straight to that skill.
- The ask is about **Juspay Payouts** rather than payment gateway checkout. This skill is PG-focused.

### What this skill does NOT do

- It does not preserve Juspay's **gateway-routing rules, health-based failover, or processor-specific metadata**. Those are orchestrator features and must be redesigned or dropped.
- It does not migrate historical Juspay orders, refunds, mandates, or analytics into Cashfree. Run both systems in parallel during cutover and keep Juspay for historical lookups until operationally safe to retire it.
- It does not auto-migrate saved cards or Juspay-managed payment method state. Future saved-card flows must be rebuilt using Cashfree Token Vault.

## 2. Concept Mapping — Read This First

Juspay and Cashfree both let you create an order, open checkout, verify status on the backend, and react to webhooks. The migration still breaks in **five predictable places**:

| # | Gotcha | Juspay | Cashfree |
|---|---|---|---|
| 1 | **Product shape** | Payment **orchestrator**. Can sit above multiple gateways and route dynamically | Direct payment gateway integration. No Juspay-style multi-PG routing layer |
| 2 | **API auth** | Basic Auth (`base64(api_key:)`) + `x-merchantid` + `x-routing-id` | `x-client-id`, `x-client-secret`, `x-api-version: 2025-01-01` |
| 3 | **Checkout handoff** | Backend returns `sdk_payload` or `client_auth_token`; frontend calls Hyper SDK `process(...)` or opens `payment_links` | Backend returns **`payment_session_id`**; frontend calls Cashfree.js or mobile SDK with that session id |
| 4 | **Webhook trust model** | Dashboard-configured Basic Auth username/password and optional custom headers on incoming webhooks | Verify `x-webhook-signature` using HMAC-SHA256 over `x-webhook-timestamp + rawBody`, then base64-compare |
| 5 | **Status model** | One order status field: `NEW`, `PENDING_VBV`, `CHARGED`, `AUTHORIZED`, etc. | Separate **order status** (`ACTIVE`, `PAID`, `EXPIRED`, `TERMINATED`) and **payment status** (`SUCCESS`, `FAILED`, `PENDING`, `USER_DROPPED`, etc.) |

### Object & Identifier Map

| Concept | Juspay | Cashfree |
|---|---|---|
| Merchant order id | `order_id` | `order_id` |
| Juspay internal order id | `id` | `cf_order_id` |
| Payment attempt id | `txn_id` / `txn_uuid` | `cf_payment_id` |
| Frontend auth / handoff token | `client_auth_token` or `sdk_payload` | `payment_session_id` |
| Refund identifier | `unique_request_id` | `refund_id` |
| Saved cards / instruments | Juspay-managed via customer + tokenization flows | Cashfree Token Vault (`instrument_id`) |

### Credential & URL Map

| | Juspay | Cashfree |
|---|---|---|
| Sandbox/Test base URL | `https://sandbox.juspay.in` | `https://sandbox.cashfree.com/pg` |
| Production base URL | `https://api.juspay.in` | `https://api.cashfree.com/pg` |
| Dashboard | `portal.juspay.in` | `merchant.cashfree.com` |
| Server auth | Basic Auth with API key as username, blank password | `x-client-id` + `x-client-secret` headers |
| Request correlation header | `x-routing-id` | No equivalent required by Cashfree |

### Status Value Map

These are **approximate operational equivalents**, not literal 1:1 values:

| Juspay | Cashfree equivalent | Notes |
|---|---|---|
| `NEW` | `ACTIVE` + payment `NOT_ATTEMPTED` | Order exists, no successful payment yet |
| `PENDING_VBV`, `AUTHORIZING`, `STARTED` | `ACTIVE` + payment `PENDING` | Keep polling / wait for webhook |
| `CHARGED` | `PAID` + payment `SUCCESS` | Safe to fulfil after backend verification |
| `AUTHORIZED` | Pre-auth flow only; inspect payment authorization state | Read `pg/backend-sdks/references/REFERENCE.md` if you need capture / void |
| `AUTHENTICATION_FAILED`, `AUTHORIZATION_FAILED`, `JUSPAY_DECLINED` | payment `FAILED` | User / bank / processor failure |
| `AUTO_REFUNDED` | payment `CANCELLED` or success + refund record, depending flow | Re-model explicitly; do not assume same semantics |

Refund status map:

| Juspay | Cashfree |
|---|---|
| `PENDING` | `PENDING` |
| `SUCCESS` | `SUCCESS` |
| `FAILURE` | `FAILED` |
| `MANUAL_REVIEW` | No direct equivalent; inspect refund status + ops workflow |

## 3. Migration Workflow

Follow these seven steps in order. If you skip the parallel-run period, you will miss state-machine and webhook regressions.

### Step 1 — Inventory the Juspay surface

Before writing Cashfree code, grep the codebase and list every place that uses:

1. Juspay backend APIs: `/session`, `/orders`, `/orders/{order_id}`, `/orders/{order_id}/refunds`, mandate / subscription APIs.
2. Headers / auth: `Authorization: Basic`, `x-merchantid`, `x-routing-id`.
3. Frontend handoff values: `sdk_payload`, `client_auth_token`, `payment_links`, Hyper SDK `process(...)`, HyperService callbacks.
4. Webhooks and event names: `ORDER_SUCCEEDED`, `ORDER_FAILED`, `ORDER_REFUNDED`, `REFUND_MANUAL_REVIEW_NEEDED`, `MANDATE_*`.
5. Status constants: `NEW`, `PENDING_VBV`, `CHARGED`, `AUTHORIZED`, `AUTO_REFUNDED`.
6. Processor-specific Juspay metadata such as `metadata.CASHFREE:*`, `metadata.PAYU:*`, `metadata.PAYTM:*`, or custom routing logic.

Keep this list. It is the cutover checklist.

### Step 2 — Decide what leaves with Juspay

Juspay often owns more than just checkout rendering. Before touching code, decide whether the merchant depends on:

- Multi-gateway routing / failover
- Dashboard-managed payment method ordering
- Juspay analytics or funnel events
- Saved cards managed through Juspay
- Mandate / subscription flows

If the answer is yes, do **not** pretend Cashfree is a literal drop-in replacement. Migrate the direct payment flow first, then rebuild needed features with adjacent Cashfree products:

- Saved cards: `pg/token-vault/SKILL.md`
- Subscriptions / mandates: `subscriptions/SKILL.md`
- Hosted URLs: `pg/payment-links/SKILL.md`
- Mobile checkout: `pg/mobile-sdks/SKILL.md`

### Step 3 — Replace server auth and rewrite order creation / verification / refunds

Node.js example:

**Before (Juspay Session API / Hypercheckout):**
```javascript
const juspayBaseUrl =
    process.env.JUSPAY_ENV === "PRODUCTION"
        ? "https://api.juspay.in"
        : "https://sandbox.juspay.in";

function getJuspayAuthHeader() {
    return "Basic " + Buffer.from(`${process.env.JUSPAY_API_KEY}:`).toString("base64");
}

app.post("/create-order", async (req, res) => {
    const orderId = req.body.orderId;
    const response = await fetch(`${juspayBaseUrl}/session`, {
        method: "POST",
        headers: {
            Authorization: getJuspayAuthHeader(),
            "Content-Type": "application/json",
            "x-merchantid": process.env.JUSPAY_MERCHANT_ID,
            "x-routing-id": req.body.customerId || orderId,
        },
        body: JSON.stringify({
            order_id: orderId,
            amount: req.body.amountRupees.toFixed(2),
            customer_id: req.body.customerId || "",
            customer_email: req.body.customerEmail,
            customer_phone: req.body.customerPhone,
            return_url: `${process.env.APP_URL}/return/${orderId}`,
        }),
    });

    const data = await response.json();
    res.json({
        orderId,
        sdkPayload: data.sdk_payload,
        paymentLinks: data.payment_links,
    });
});

app.get("/verify/:orderId", async (req, res) => {
    const response = await fetch(`${juspayBaseUrl}/orders/${req.params.orderId}`, {
        headers: {
            Authorization: getJuspayAuthHeader(),
            "x-merchantid": process.env.JUSPAY_MERCHANT_ID,
            "x-routing-id": req.query.customerId || req.params.orderId,
        },
    });
    const order = await response.json();
    if (order.status === "CHARGED") {
        fulfillOrder(req.params.orderId);
        return res.json({ status: "CHARGED" });
    }
    res.json({ status: order.status });
});

await fetch(`${juspayBaseUrl}/orders/${orderId}/refunds`, {
    method: "POST",
    headers: {
        Authorization: getJuspayAuthHeader(),
        "Content-Type": "application/json",
        "x-merchantid": process.env.JUSPAY_MERCHANT_ID,
        "x-routing-id": customerId || orderId,
    },
    body: JSON.stringify({
        unique_request_id: `refund_${Date.now()}`,
        amount: refundAmountRupees,
        metaData: { description: "Customer request" },
    }),
});
```

**After (Cashfree):**
```javascript
import { Cashfree, CFEnvironment } from "cashfree-pg";

const cashfree = new Cashfree(
    process.env.CASHFREE_ENV === "PRODUCTION"
        ? CFEnvironment.PRODUCTION
        : CFEnvironment.SANDBOX,
    process.env.CASHFREE_APP_ID,
    process.env.CASHFREE_SECRET_KEY,
);

app.post("/create-order", async (req, res) => {
    const orderId = req.body.orderId;
    const response = await cashfree.PGCreateOrder({
        order_id: orderId,
        order_amount: req.body.amountRupees,
        order_currency: "INR",
        customer_details: {
            customer_id: req.body.customerId || `guest_${orderId}`,
            customer_phone: req.body.customerPhone || "9999999999",
            customer_email: req.body.customerEmail,
            customer_name: req.body.customerName,
        },
        order_meta: {
            return_url: `${process.env.APP_URL}/return/${orderId}`,
            notify_url: `${process.env.APP_URL}/webhook`,
        },
        order_note: req.body.note,
    });

    res.json({
        orderId,
        paymentSessionId: response.data.payment_session_id,
    });
});

app.get("/verify/:orderId", async (req, res) => {
    const order = await cashfree.PGFetchOrder(req.params.orderId);
    if (order.data.order_status === "PAID") {
        fulfillOrder(req.params.orderId);
        return res.json({ status: "PAID" });
    }
    res.json({ status: order.data.order_status });
});

await cashfree.PGOrderCreateRefund(orderId, {
    refund_id: `refund_${Date.now()}`,
    refund_amount: refundAmountRupees,
    refund_note: "Customer request",
});
```

**Key rewrites:**

- Delete all Juspay auth helpers. Cashfree does **not** use Basic Auth, `x-merchantid`, or `x-routing-id`.
- Replace `sdk_payload` / `client_auth_token` with **`payment_session_id`**.
- Replace `status === "CHARGED"` with `order_status === "PAID"` and inspect payment status if you need attempt-level detail.
- Map `unique_request_id` to a merchant-generated Cashfree `refund_id`. Also add `x-idempotency-key` if using raw Cashfree REST calls.
- Remove gateway-specific `metadata.*` unless there is a Cashfree-native field for it.

### Step 4 — Replace frontend checkout handoff

Juspay frontend flows consume a **process payload** (`sdk_payload`) or a `client_auth_token`. Cashfree frontend flows consume **`payment_session_id`**.

**Before (Juspay):**
```javascript
const { sdkPayload } = await fetch("/create-order", {
    method: "POST",
    body: JSON.stringify(cart),
}).then((r) => r.json());

// Hypercheckout / Express Checkout platform SDKs all consume Juspay-generated payloads.
hyperInstance.process(sdkPayload);
```

**After (Cashfree Web Checkout):**
```html
<script src="https://sdk.cashfree.com/js/v3/cashfree.js"></script>
<script>
const cashfree = Cashfree({ mode: "sandbox" }); // or "production"

async function startPayment() {
    const { orderId, paymentSessionId } = await fetch("/create-order", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(cart),
    }).then((r) => r.json());

    cashfree
        .checkout({
            paymentSessionId,
            redirectTarget: "_self",
        })
        .then(async (result) => {
            if (result.error) return console.error(result.error);
            const verify = await fetch(`/verify/${orderId}`).then((r) => r.json());
            if (verify.status === "PAID") {
                // render success UI
            }
        });
}
</script>
```

If the existing project is mobile, the equivalent replacement is **Juspay Hyper SDK / Express Checkout SDK → Cashfree mobile SDK**. Use `pg/mobile-sdks/SKILL.md` plus REFERENCE §9 in this skill.

### Step 5 — Rewrite webhooks

Juspay webhook verification is based on dashboard-configured **Basic Auth / custom headers**. Cashfree webhook verification is **payload signature verification**.

**Before (Juspay):**
```javascript
app.post("/webhook", express.json(), (req, res) => {
    const auth = req.headers.authorization || "";
    const expected =
        "Basic " +
        Buffer.from(
            `${process.env.JUSPAY_WEBHOOK_USERNAME}:${process.env.JUSPAY_WEBHOOK_PASSWORD}`,
        ).toString("base64");

    if (auth !== expected) return res.sendStatus(401);

    switch (req.body.event_name) {
        case "ORDER_SUCCEEDED":
            handleSuccess(req.body);
            break;
        case "ORDER_FAILED":
            handleFailure(req.body);
            break;
        case "ORDER_REFUNDED":
            handleRefund(req.body);
            break;
    }

    res.sendStatus(200);
});
```

**After (Cashfree):**
```javascript
import crypto from "crypto";

app.post("/webhook",
    express.raw({ type: "application/json" }),
    (req, res) => {
        const timestamp = req.headers["x-webhook-timestamp"];
        const signature = req.headers["x-webhook-signature"];
        const expected = crypto
            .createHmac("sha256", process.env.CASHFREE_SECRET_KEY)
            .update(String(timestamp) + req.body.toString())
            .digest("base64");

        if (expected !== signature) return res.sendStatus(400);

        const event = JSON.parse(req.body.toString());
        switch (event.type) {
            case "PAYMENT_SUCCESS_WEBHOOK":
                handleSuccess(event.data);
                break;
            case "PAYMENT_FAILED_WEBHOOK":
            case "PAYMENT_USER_DROPPED_WEBHOOK":
                handleFailure(event.data);
                break;
            case "REFUND_STATUS_WEBHOOK":
                handleRefund(event.data);
                break;
        }

        res.sendStatus(200);
    });
```

**Event-name map (most common):**

| Juspay | Cashfree |
|---|---|
| `ORDER_SUCCEEDED` | `PAYMENT_SUCCESS_WEBHOOK` |
| `ORDER_FAILED` | `PAYMENT_FAILED_WEBHOOK` or `PAYMENT_USER_DROPPED_WEBHOOK` |
| `TXN_CREATED` | No fulfilment event; inspect payment attempt lifecycle if needed |
| `ORDER_REFUNDED` | `REFUND_STATUS_WEBHOOK` with `refund_status === "SUCCESS"` |
| `ORDER_REFUND_FAILED` | `REFUND_STATUS_WEBHOOK` with `refund_status === "FAILED"` |
| `REFUND_MANUAL_REVIEW_NEEDED` | No direct 1:1 event; escalate operationally |
| `MANDATE_*` | Subscription webhook family — see `subscriptions/SKILL.md` |

### Step 6 — Rebuild the status / fulfilment logic

A Juspay migration fails if the business logic still expects `CHARGED` to be the single source of truth.

Cashfree best practice:

1. Use **backend order fetch** after return / callback.
2. Fulfil only when `order_status === "PAID"`.
3. If you need attempt-level behaviour, read `GET /pg/orders/{order_id}/payments` and inspect `payment_status`.
4. Continue listening to webhooks because redirections and user callbacks are not reliable.

This is the place to update:

- Payment success conditions
- Retry / pending screens
- Auto-refund / late-success handling
- Refund tracking logic
- BI / internal event names derived from Juspay statuses

### Step 7 — Parallel-run, then cut over

1. Keep Juspay and Cashfree live behind a provider flag in sandbox.
2. Validate success, failure, refund, and webhook flows on Cashfree end-to-end.
3. Shadow a small percentage of production traffic to Cashfree.
4. Compare conversion, failure mix, refund processing, and webhook delivery across both systems.
5. Retire Juspay only after delayed webhooks, refunds, and mandate callbacks for old orders are operationally irrelevant.

## 4. Security Constraints — Never Violate

1. **Never send `x-client-secret` to the client.** Juspay's client-facing handoff was `sdk_payload` / `client_auth_token`; Cashfree's is `payment_session_id`.
2. **Never keep Juspay webhook Basic Auth as the only protection after cutover.** Cashfree webhook authenticity depends on signature verification over the raw body.
3. **Never fulfil from a client callback alone.** Juspay and Cashfree both recommend backend verification. On Cashfree that means `PGFetchOrder` / `GET /pg/orders/{order_id}`.
4. **Never assume Juspay status names map directly.** Rewrite the state machine explicitly; do not string-replace `CHARGED` with `SUCCESS`.

## 5. Quick Diagnostic — "My migration broke"

| Symptom | Likely cause | Fix |
|---|---|---|
| Cashfree APIs return `401` | Still sending Juspay Basic Auth / `x-merchantid` | Switch to `x-client-id`, `x-client-secret`, `x-api-version` |
| Frontend cannot open checkout | Code still expects `sdk_payload` / `client_auth_token` | Return `payment_session_id` and wire Cashfree.js / mobile SDK |
| Payments complete but orders are never fulfilled | Code still waits for `status === "CHARGED"` | Re-fetch Cashfree order and fulfil only on `order_status === "PAID"` |
| Webhook verification fails every time | Reusing Juspay Basic Auth webhook logic | Capture raw body and verify `x-webhook-signature` using `x-webhook-timestamp + rawBody` |
| Refund dedupe errors / duplicate refunds | Reusing Juspay `unique_request_id` semantics loosely | Generate a unique Cashfree `refund_id`; add `x-idempotency-key` on raw REST calls |
| Saved cards disappeared after migration | Juspay-managed instruments are not portable | Rebuild with `pg/token-vault/SKILL.md` for future traffic |
| Shareable payment URL is missing | Code depended on Juspay `payment_links` from session flow | Use Cashfree PG checkout for in-app flows, or `pg/payment-links/SKILL.md` for hosted shareable links |
| Conversion drops after cutover | Juspay routing/fallback features were masking processor failures | Treat this as a product / routing redesign issue, not just a code bug |

Cross-reference `common-mistakes/SKILL.md` for the generic integration debugging tree once the provider-specific migration bugs are fixed.
